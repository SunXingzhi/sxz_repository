# L1 Cache & L2 Cache

> Reference:https://blog.csdn.net/tilblackout/article/details/131146518

L1分为Dcache(数据缓存)和ICache(指令缓存), 两者在Cortex M7上定义为32KB, 同时, 每个缓存会分成32Byte为一行的缓存行(Cache line), 并且每行有一个标记, 用于cpu查找指定行. DCache 每四行作为一个缓存组, ICache 每2行作为一个缓存组.

当CPU想要访问数据时, 会先去L1Cache 找, 如果没有, 再去L2(如果设置有L2的情况下. CortexM7是没有的), 如果都没有, 再去主存寻找, 同时拷贝一份数据到缓存中, 在下次访问相同地址的数据时, 就可以直接访问缓存数据了, 加快了速度.



# MPU-内存保护单元

通过MPU, 我们就可以规定出内存地址范围内的任意一个区域(在硬件支持的分度值以上, 比如32字节以上的区域)的内存属性(R, W, 是否共享等等这里的共享同样可以.)

这里的文章以Cortex-M7为例, 讲述了MPU的功能以及配置要求等等. Reference:https://blog.csdn.net/tilblackout/article/details/131146513. 同时在文章中有个疑问是: 为什么S=1, 系统就要被强制设置为non-cacheable, `TEX,C,B `全无效?

> A: 这里需要结合硬件来说. 如果了解过freertos等系统的话可以清楚数据同步这个概念, 例如使用的信号量, 任务通知, 消息队列等等, 本质上都是多个任务(进程)在读写同一个共享资源时, 不会因为其中一个任务改写了数据, 导致其他任务读取的还是旧数据. 不过这是由软件控制的, **而硬件同样可以对其进行控制**. 比如CPU, DMA可以访问同一块内存, 此时就与刚才说的情景相同了, 这时如果硬件支持同步(就是所说的**缓存一致性**), 则其中一个对数据改写了, 硬件会自动通知另一个角色数据更改了, 更新数据. 而无需软件对其进行设置了. 解释清楚这里后, 再回去解释这里的`S, TEX,C,B`问题. 因为数据同步本质上和缓存是冲突的, 为什么这么说? 我们以**CPU L1Cache**为例, CPU 可以通过建立系统某块内存的数据副本,拷贝到L1Cache中, 这样当CPU访问时先去请求L1, 看看有没有该地址的数据, 如果由就直接拿, 相比与去主存拿(SRAM, DDR)加快了CPU的拿数据效率. 但是这种方式是假设这块内存不会被其他角色更改的, 而如果有多个角色都会访问这个数据, 并进行读写操作, 真实地址本身的数据会不断改变, 而CPU自己缓存上的数据还没变, 这样就产生了数据不同步的问题. 而如果想要数据共享, 则就不能有缓存机制, 而是每次CPU都直接访问主存, 防止数据被其他人更改的问题(程序本身更改, 外部DMA数据, 通讯设备数据更改等等方式, 都会把数据在CPU不知情的情况写更改). 因此在Cortex M7为代表的硬件不支持**缓存一致性**的cpu, 当表明数据可以被共享(同步)时, 则系统强制关闭了该内存的缓存属性, 设置为`non-cacheable`. 但是如果CPU硬件本身就支持缓存一致性, 那么就没有这个问题了, CPU可以在有缓存的情况下同时支持数据同步功能.
